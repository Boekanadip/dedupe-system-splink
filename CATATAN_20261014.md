## 2. Fix TF inkremental (direkomendasikan #1 dan #3)

**Masalah (terukur):** `score_new_pairs` memberi Splink hanya frame kandidat
(2.181 baris), sehingga TF dihitung dari frame bias — kunci blocking
terwakili berlebihan (`saputra` tampak 1,47% vs 0,146% korpus). Delta
skor 100% dari TF (TF-off delta = 0,000); atribusi: last_name +3,33,
state +2,11. Dampak: 6 dari 2.103 pasangan berubah keputusan, 1 MATCH edge
bergeser (p 0,30 vs 0,94).

**Fix:** `src/incremental.py` — `corpus_tf_tables()` menghitung TF dari
`PROCESSED_DATA_PATH` (parquet yang sama dengan `splink_model.load_data`),
didaftrakan via API resmi `linker.table_management.register_term_frequency_lookup`
sebelum predict. Kolom TF diturunkan dari `tf_adjustment_column` model
tersimpan, bukan daftar tetap.

**Hasil:** check `incremental_candidate_prefilter_is_exact` kini PASS —
2.103 pasangan + 13 MATCH edges identik, max drift 0,0. Smoke suite 43/44
(satu FAIL = registry batch_0018, lihat atas).
